# 命名规范

## POSIX shell

- 遵循 [Google Shell 风格指南](https://google.github.io/styleguide/shell.xml)

## Go

- [Go Code Review Comments](https://github.com/golang/go/wiki/CodeReviewComments)
- [Effective Go](https://golang.org/doc/effective_go.html)
- 了解并规避 [Go landmines](https://gist.github.com/lavalamp/4bd23295a9f32706a48f)
- 写注释：
  - 遵循 [Go 注释约定](http://blog.golang.org/godoc-documenting-go-code)；
  - 如果代码评审者对"为什么这样写"提出疑问，说明这里需要补注释。
- 命令行参数用连字符（`-`），不要用下划线。
- 命名：
  - 接口命名考虑包名，避免冗余，例如 `storage.Interface` 优于 `storage.StorageInterface`；
  - 包名不使用大写、下划线或连字符；
  - 包名与所在目录名保持一致，例如 `pkg/controllers/autoscaler/foo.go` 应为 `package autoscaler`。

## 文件与目录命名

- 普通文件可用连字符（`-`）或下划线（`_`），优先下划线，例如 `data_processor.go`；
- 脚本与 Markdown 文件用连字符，例如 `deploy-script.sh`、`project-overview.md`；
- 大写开头的 Markdown 文档（如 `README`）必要时可用下划线分词，例如 `README_SETUP.md`；
- 目录名只用连字符，例如 `image-assets`；
- 配置文件（`.yaml` 等）用连字符，例如 `app-config.yaml`；
- Go 源文件名全小写，用下划线分隔；
- 包名与目录名一致。

## 最佳实践

- 名称简洁但能表意，一眼看出文件用途；
- 名称中不使用空格；
- 尽量全小写，避免大小写敏感系统出问题；
- 需要版本/日期时按 `project-plan-v1.2.md`、`backup-2023-03-15.sql` 格式。

## 测试规范

单元测试与被测代码同包放置，命名 `xxx_test.go`，使用标准库 `testing`（本项目核心模块的测试在第三步补齐）。
