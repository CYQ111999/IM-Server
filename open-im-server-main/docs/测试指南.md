# 测试指南

## 一、现状说明

本项目（基于 OpenIM Server v3.8 二次开发）**没有** `Makefile`、也没有 `scripts/install/test.sh`，构建统一使用 Mage。因此上游文档里的 `make test`、`openim::test::xxx` 等命令在本项目中**不存在**，请勿照用。

当前可用的测试手段有两种：

1. **Go 单元测试** —— 直接 `go test`，覆盖存储层、缓存、工具包等纯逻辑模块；
2. **端到端（e2e）测试** —— `test/e2e` 目录，基于 Ginkgo 编写，需要完整环境跑起来。

## 二、运行单元测试

### 全量运行

```bash
go test ./...
```

### 只跑某个包

```bash
go test ./pkg/common/storage/cache/redis/...
go test ./pkg/localcache/...
go test ./pkg/tools/batcher/...
```

### 详细输出与单个用例

```bash
# -v 打印每个用例的名称与结果
go test -v ./pkg/localcache/...

# -run 用正则匹配用例名，只跑指定的用例
go test -v -run TestBatcher ./pkg/tools/batcher/

# -race 检测数据竞争（并发代码建议必跑）
go test -race ./pkg/localcache/...

# -count=1 禁用测试结果缓存
go test -count=1 ./pkg/common/convert/
```

### 查看覆盖率

```bash
go test -cover ./...
go test -coverprofile=cover.out ./pkg/localcache/...
go tool cover -html=cover.out    # 生成 HTML 报告
```

## 四、写单元测试的约定

1. **文件命名为 `xxx_test.go`**，与被测文件同包，便于访问包内未导出函数。
2. **优先测纯逻辑**：序号计算、消息过滤、协议转换、缓存键拼装等不依赖外部中间件的函数。
3. **依赖外部中间件的用例**：Mongo、Redis、Kafka 相关的测试需要中间件先启动（见《开发指南》）。这类测试在没有环境时应可跳过，不要让它阻塞 `go test ./...`。
4. **表驱动**：多用 `tests := []struct{ name string; ... }` + `t.Run` 的写法，一个函数覆盖多种输入。

示例：

```go
func TestSplitIntoBatches(t *testing.T) {
	tests := []struct {
		name      string
		keys      []string
		batchSize int
		want      int
	}{
		{"整除", []string{"a", "b", "c", "d"}, 2, 2},
		{"有余数", []string{"a", "b", "c"}, 2, 2},
		{"空输入", nil, 2, 0},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := len(splitIntoBatches(tt.keys, tt.batchSize)); got != tt.want {
				t.Fatalf("批次数 = %d, 期望 %d", got, tt.want)
			}
		})
	}
}
```

5. **断言清晰**：失败信息里带上「实际值 vs 期望值」，否则排查成本比不写测试还高。

## 五、端到端测试（e2e）

`test/e2e` 使用 Ginkgo + Gomega，覆盖注册登录、好友、群组、消息收发等完整链路。

运行前提：

1. 中间件（MongoDB / Redis / etcd / Kafka / MinIO）已通过 `docker compose` 启动；
2. 服务端已启动（`mage start`）；
3. 配置中的 API 地址、管理员账号与运行环境一致。

e2e 测试依赖真实服务，改动核心链路后建议跑一遍；日常迭代以单元测试为主。

## 六、建议的测试节奏

- 改完一个模块：跑该模块的 `go test ./该包/...`；
- 提交前：跑 `go build ./...` + `go test ./...`；
- 改并发相关代码（缓存、批量器、序号分配）：加跑 `-race`；
- 改消息链路：启动环境后跑 e2e 关键用例。
