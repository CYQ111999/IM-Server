# 错误码规范

错误码是用户定位和解决问题的重要手段。应用遇到异常时，用户可以依据文档中错误码的描述与解决方案快速定位并处理问题。

## 错误码命名规范

- 遵循驼峰命名（CamelCase）；
- 错误码分两级，用 `.` 分隔，例如 `InvalidParameter.BindError`：第一级为平台级错误码，第二级为资源级错误码，可按场景自定义；
- 第二级错误码只能使用英文字母或数字（`[a-zA-Z0-9]`），应使用标准英文单词拼写、标准缩写、RFC 术语缩写等；
- 同一语义的错误码避免重复定义，例如不要同时存在 `InvalidParameter.ErrorBind` 和 `InvalidParameter.BindError`。

## 一级常用错误码

| 错误码 | 描述 | 错误类型 |
| --- | --- | --- |
| `InternalError` | 内部错误 | 1 |
| `InvalidParameter` | 参数错误（含参数类型、格式、取值等错误） | 0 |
| `AuthFailure` | 认证/鉴权错误 | 0 |
| `ResourceNotFound` | 资源不存在 | 0 |
| `FailedOperation` | 操作失败 | 2 |

> 错误类型：0 表示客户端问题，1 表示服务端问题，2 表示客户端/服务端皆有可能。
